# TCP/UDP ACL、模板与防火墙设计

## 1. 范围与当前状态

本方案仅覆盖 IPv4 TCP/UDP 公网来源访问控制、连接状态、Agent IPv4 目标访问边界和相关宿主机过滤。HTTP(S) 的双栈入口和 Agent—服务器的双栈承载不接入用户业务的这套 ACL 或模板；承载认证与节点接入防护独立处理。

当前只设计管理与执行机制，不编写、内置、导入或启用任何具体 ACL。模板名称、来源 IP/CIDR、地区集合、允许/拒绝条目和默认模板选择，均由管理员后续添加。用户提到的按境内外划分的模板属于管理员可配置的使用场景，不作为系统预置策略。

本文为目标设计，已有策略引擎、地址库与验证记录以 [实现与验收记录](../reference/IMPLEMENTATION.md) 为准。2026-11-01 仅同步网络职责与地址族范围，不重设计中控模板模型，也不修改宿主机网络配置。

## 2. frp 现有能力与补充目标

以已核对的 frp v0.71.1 为参考：

| 现有机制 | 能力及边界 |
| --- | --- |
| Token / OIDC | 验证客户端身份，不等于公网访问者来源 ACL |
| allowPorts / maxPortsPerClient | 约束客户端可申请的公网端口及数量，不是访问者来源地址过滤 |
| NewUserConn 服务端插件 | 普通 TCP 路径携带 RemoteAddr，可在分配工作连接前拒绝访问 |
| UDP 转发路径 | 已核对路径没有与 TCP NewUserConn 对应的逐来源统一钩子 |
| STCP / XTCP / SUDP 的 allowUsers | 面向这些模式的访问者用户授权，不等于普通公网 TCP/UDP 的来源 ACL |

因此不将 frp 描述为完全没有访问控制。本项目补充的是普通 TCP/UDP 一致的策略模型、管理员模板、状态清理、本地执行及云控解释能力。

## 3. 管理员模板与默认绑定

### 3.1 模板生命周期

管理员可以创建、编辑、发布、停用和归档模板，配置可使用该模板的租户、设备或规则范围。普通用户只能查看和绑定被授权的模板；是否允许自定义规则或替换默认模板，由管理员授权。

模板包含元信息和策略内容两部分。机制所需字段如下，仅定义数据结构，不提供任何实际条目：

| 字段 | 用途 |
| --- | --- |
| template_id / owner_scope | 稳定模板身份与管理归属 |
| name / description | 管理员填写的名称和说明 |
| draft_revision / published_revision | 草稿与已发布版本分离 |
| applicable_protocols | 可绑定的 TCP/UDP 协议范围 |
| policy_definition | 管理员编写的匹配条件、动作和默认动作 |
| allowed_binding_scope | 允许绑定的资源范围 |
| created_by / updated_by / timestamps | 操作审计 |

新建模板从空草稿开始，不自动生成规则。草稿编辑不影响数据面；发布前校验语义和执行能力，并展示受影响规则。发布产生不可变版本，回滚也创建新版本。

模板可被多台 Agent 的多条规则引用，但运行授权仍绑定各自的租户、设备、会话和规则；共享模板不产生跨设备转发权。云控只向各节点下发其所需内容。

### 3.2 默认模板与强制策略

默认模板表示创建新 TCP/UDP 规则时的默认选择；强制策略表示管理员要求持续满足的上级限制，两者分开配置。

- 管理员配置默认模板及适用范围；不由系统选择一份预置模板。
- 多层默认设置按规则所属设备、租户、平台的顺序寻找最具体的一项，得到一个默认选择；独立存在的强制策略仍全部生效。
- 新规则保存实际选用的模板引用及其来源。修改默认模板指针只影响后续新建规则，不自动替换已有规则的绑定。
- 发布某个已引用模板的新版本，会为所有引用它的规则生成新的期望策略快照，并展示各节点的应用进度。
- 用户是否能替换默认选择，由授权决定；用户条目不能放宽任何强制上级策略。
- 已引用模板不能直接删除。需要先显式迁移绑定；归档只禁止新增绑定，不静默解除已有策略。

系统不预填全放行或全拒绝模板。管理员显式配置 ACL 是否启用；上级要求启用时，下级不能关闭。要求启用却没有有效策略、模板缺失或所需能力不足的规则不得标为就绪，也不开放相应转发。显式停用来源 ACL 仅跳过这一检查，设备授权、目标绑定和资源限制仍执行。

### 3.3 地区匹配能力

为管理员后续编写地区类模板，匹配模型可支持 GeoIP 国家/地区集合。集合内容、地区边界、未知地址的处理及具体允许/拒绝动作均由管理员填写，不预设“国内”对应哪些地区，也不预装境内外地址清单。

地区匹配使用边缘实际观测到的公网源 IP，在边缘本地查询受信任、版本化的地址库或已编译前缀集合，不逐连接向云控或在线地理服务查询。来源 CIDR 与地区集合可以在同一模板中使用。

GeoIP 返回国家/地区标识、未知或不适用等明确结果。使用地区条件的策略必须显式声明未知结果如何处理，不能把查询失败当成条件未命中后意外放行。IP 地区只描述地址库中的网络归属，不代表访问者的物理位置或身份。

地址库来源、更新周期、版本和有效期由管理员配置。更新与策略一样先验证再原子切换，触发受影响流的重新判断；未安装地址库或能力不支持时，地区条件不可发布到对应节点。更新失败保留仍有效的旧版本并报告，旧版本到期后停止依赖它的转发，不自动关闭地区检查。此处只定义能力，不选定、下载或生成实际地址库。

## 4. 策略语义与多设备隔离

### 4.1 生效层级

来源访问需要同时满足所有适用层级：平台/边缘强制限制、租户限制、设备限制和规则绑定策略。某层拒绝时，子层允许不能覆盖；默认模板本身不等同于不可覆盖的上级限制。

同一策略内部按显式、唯一的 priority 从小到大首次匹配，执行该条目的 allow 或 deny。没有匹配条目时执行管理员明确填写的 default_action；缺失默认动作不允许发布。多个策略之间取允许集合的交集，不混用跨策略的优先级。

空条目集合仍执行显式默认动作，不根据条目数量推断是黑名单还是白名单。新增临时条目同样遵守层级与排序，不能越过上级拒绝；到期时间在节点本地执行。

### 4.2 匹配字段

| 维度 | 含义 |
| --- | --- |
| 协议 | TCP 或 UDP，必须与规则类型一致 |
| 来源地址 | 当前 TCP/UDP 数据面使用解析后的 IPv4 地址、CIDR 或管理员地址组 |
| 来源地区 | 可选的、依赖已配置地址库的国家/地区集合 |
| 公网目的 | 转换前的入口 IP、目的端口和对应规则 |
| 来源端口 | 可选高级条件，不能当作稳定的用户身份 |
| 资源范围 | 从可信配置获得的 tenant_id、device_id、edge_id、rule_id |
| 生效时间 | 可选起止时间或到期时间，由节点本地执行 |

单个条目的不同维度取交集，同一维度的集合取并集；省略某个可选匹配维度表示该维度不限，空集合视为配置错误。地区查询异常按显式异常处理动作执行，不依赖普通条目排序兜底。

地址组、策略和模板引用均校验归属及使用授权，不接受 Agent 自报租户或跨租户对象 ID。地址使用结构化解析和前缀比较，IPv4-mapped IPv6 规范化为 IPv4，真正 IPv6 来源不进入四层业务数据面。既有通用策略格式和地址库可以继续解析 IPv6，本轮不迁移其数据模型，也不据此扩大转发支持范围。

公网源身份来自边缘接收的实际连接或报文，不使用 Agent 隧道对端地址、内部服务地址或用户自报数据。UDP 来源地址和端口不提供用户认证；防火墙不能据此消除公网 UDP 的源地址伪造问题。

### 4.3 运行绑定

策略快照记录 policy_id/revision、模板发布版本、地址组版本及可选的地址库版本，生成 effective_policy_revision。每个活动流同时关联设备会话、规则版本、原始五元组和该生效策略版本。

规则从 Agent A 转到 Agent B 时重新计算 B 的适用策略与目标访问范围，关闭 A 的旧流。不能因为同账号或同模板就复用 A 的流授权、UDP 映射或策略缓存。

## 5. 执行路径

~~~mermaid
flowchart LR
    Visitor["公网 TCP/UDP"] --> Edge["边缘：识别原始五元组与规则"]
    Edge --> ACL["本地来源 ACL / 连接状态检查"]
    ACL --> Budget["账号与边缘资源准入"]
    Budget --> Tunnel["绑定设备会话和规则的隧道"]
    Tunnel --> TargetACL["Agent：目标地址与流授权检查"]
    TargetACL --> Target["socket 或受限 TUN 到目标"]
~~~

模板发布、策略下发和统计上报都不进入逐包热路径。节点接收版本化快照，预先编译本地索引；缓存键必须包含规则、会话和生效策略版本，不能只按源 IP 缓存一个永久允许结果。

先做来源准入，再为允许的新流预留账号并发许可、创建隧道业务流；后续失败要退回未使用许可。节点在此前仍需执行有界队列、PPS 等自身保护，拒绝流量也会消耗物理链路和处理能力。

被来源 ACL 拒绝的业务不进入 Agent，也不作为已转发业务载荷计入账号流量；节点实际收到的字节仍进入物理统计。ACL 拒绝、资源限流、Agent 离线和目标不可达分别计数。

## 6. TCP 与 UDP 状态防火墙

### 6.1 TCP

socket 模式在 accept 后、分配 Agent 逻辑流前校验来源策略。此时公网 TCP 握手可能已经完成；只有经过验证的内核前置过滤才可在更早阶段丢弃，不能把应用 ACL 宣称为握手前防护。

允许连接建立受规则、会话和授权期限约束的活动状态。策略收紧后重新判断已有连接，终止不再获准的连接；不能只阻止后续新连接。终止单个业务流不能关闭同一复用承载中的其他合法流。

TCP 拒绝时关闭连接；需要内核 DROP 或 REJECT 时按后端能力配置。不会向原始业务字节流插入 HTTP 错误页或额外代理头。

### 6.2 UDP

UDP 以规则、设备会话、原始来源/入口地址与端口建立精确伪会话，设置空闲超时、会话上限和新会话速率限制。只有获准入站报文才能创建映射；目标返回报文本身不能创建新的公网映射。

返回报文必须匹配该规则的目标、已授权会话和反向流身份。来源端口变化按新流判断；映射到期或策略收紧后，不再接受旧状态返回的报文，也不能把报文交给同账号另一台 Agent。

拒绝 UDP 时丢弃报文，不创建目标 socket 或 TUN 映射，记录有界统计。不能用“所有来自 Agent 的 UDP”代替逐流返回校验。

### 6.3 内核状态与协议解析

TUN/内核转发不能以无条件 ESTABLISHED 放行绕过规则撤销、策略更新或租约到期。维护可定位到规则和会话的流标记/连接跟踪域，并在必要时阻断及清理相应状态，保留其他租户和宿主机连接。

端口过滤不能让非首片绕过检查。服务器 socket 路径使用内核交付的完整报文；客户端 TUN 的 IPv4 回包需要受限重组或经过验证的关联机制，无法安全关联的分片不进入协议栈。异常报文、分片缓存和重组资源有明确上限；IPv6 扩展头解析不作为业务转发能力。

客户端 TUN 的 MTU、IPv4 分片和隧道 UDP 分段分别管理。通用 ICMP 与动态 PMTU 业务通告不在当前支持范围；外层 IPv4/IPv6 承载的 MTU 处理沿用所选传输实现，不能将其宣称为业务 ICMP 转发。

## 7. Agent 目标边界与 TUN

来源 ACL 和目标访问限制分别判断。服务器从普通 IPv4 socket 取得实际访客五元组，经认证承载传给 Agent；服务器没有 TUN 或 DNAT。Agent 使用最终 IPv4 目标地址、端口和设备本地允许范围，不能把外层承载的 IPv4/IPv6 对端当成访客来源。

Agent 的有效目标为云控批准的规则目标与设备本地允许范围的交集。管理员可限制可发布的目标，设备本地也可进一步收紧；不能因为启用 TUN 就允许访问任意目的地。

目标可以是本机或局域网 IPv4 服务，不统一禁止 loopback 或私有地址。目标为域名时，由 Agent 解析并逐个验证 IPv4 候选，实际拨号使用已验证的地址，后续重解析同样检查。只有 AAAA 或仅有被拒绝的 IPv4 时不创建目标连接，不借助 NAT64 或静默改成 IPv6 转发。

socket 和 TUN 路径遵守相同来源策略与目标授权。仅向 TUN 注入已授权流的包，返回包必须匹配所属流；保源模式不允许因执行 ACL 而悄悄改写来源端口或降级为 PROXY v2。回程路径等保源前提仍按 [来源信息传递与 TUN 设计](transparent-source-design.md) 验证。

## 8. 宿主机防火墙后端

应用层策略是基础执行点；内核过滤作为按平台能力启用的执行后端。云控显示实际能力，不把无管理员权限下的应用 ACL 显示成完整内核防火墙。

服务器普通监听的应用 ACL 与 Linux 客户端的 TUN/透明 socket 回流保护分别验证。客户端只按本项目拥有的接口和精确流元组安装必要规则；服务器保源不安装 TUN、DNAT 或策略路由。其他可选 Linux 防火墙后端需独立验证，不能把存在某个网络接口当作策略已生效。

只管理本项目拥有的过滤、NAT 和路由对象，不清空宿主机规则，不接管其他服务、容器或管理连接。云控和 Agent 承载连接不能被错误纳入用户业务 ACL；清理操作也按归属定位。

Windows 客户端仅支持普通 socket 转发和 HTTP 来源头，不开发 Wintun/WFP 保源后端。规则要求的原生保源或内核执行能力不满足时报告能力缺失，不能静默跳过。

本项目的允许结果只表示自己的策略允许，不保证云安全组、上游设备和宿主机其他规则允许。诊断中保留这一执行边界。

## 9. 发布、失联与已有流处理

发布流程：校验模板和引用权限 → 编译受影响节点的完整快照 → 下发 → 本地校验与原子切换 → 清理不再允许的状态 → 上报应用结果。

- 来源策略收紧在边缘应用时立即阻止不再允许的新流；Agent 目标策略收紧在 Agent 应用时阻止相应目标转发。
- 已有流按新快照重新判断；首阶段无法精确筛选时可以关闭受影响规则的全部旧流，并在发布预览中明确影响。
- ACK 表示新快照已生效且旧状态已清理或已被可靠阻断，不只是已收取配置。清理失败时暂停受影响转发并报告错误。
- 地址组、GeoIP 数据版本和临时条目到期都视为可能影响许可集合的变化，不能保留旧缓存绕过。
- 跨节点不承诺瞬间同时更新；面板区分期望、边缘已应用和 Agent 已应用版本。放宽权限仍需相关节点及规则就绪才能提供服务。
- 无效更新不覆盖最近有效快照，节点报告失败；旧快照只能在其既有授权和有效期内继续。新建规则没有有效快照时不开放。
- 云控失联时只在有效配置及授权租约内继续。到期关闭相关业务和内核转发状态；快速转发路径也必须执行期限限制。
- 策略同步与统计上报独立。不能等到下一次统计上报才应用已经收到的限制；也不能把未收到 ACK 的发布显示为全部生效。

## 10. 云控交互与诊断

面板提供模板草稿、发布版本、默认适用范围、强制策略和引用规则清单。创建规则时显示默认选择来自哪一层、用户是否可修改，以及实际继承的完整策略链。

策略编辑支持排序冲突、无效引用、已过期条目和可判定的遮蔽关系检查。管理员自行新增临时条目时设置期限，节点本地到期失效；不由系统生成具体允许项。

提供“这次访问为什么被拒绝”的模拟：输入协议、来源地址/端口与公网入口，输出适用策略链、匹配条目或默认动作、模板版本及可选的地区查询版本/结果。模拟只解释指定快照下的 ACL 判断，不保证公网连通性或账号剩余额度。

运行视图区分来源拒绝、目标范围拒绝、策略尚未应用、地址库不可用、账号/节点限流、Agent 离线和目标连接失败。没有观测到访问时标记证据不足，不能直接断定是本项目 ACL 拦截。

命中数、拒绝数和流状态按周期合并上报，附统计截至时间。详细来源日志采样并限量，指标避免以任意公网 IP 建立无界标签；日志压力不能变成逐包访问云控。

## 11. 实现顺序与后续验收

先实现管理员空模板管理、默认绑定与权限语义，再验证单边缘 TCP/UDP 的本地来源判断、目标校验和状态撤销。多设备共享模板要保持独立授权；内核前置过滤和地区匹配按实际能力逐步开放，不提前显示为已支持。

以下为目标验收条件，已完成项以 IMPLEMENTATION.md 为准；本轮不生成实际 ACL 或执行网络测试：

1. 初始安装没有预置策略内容、地区清单或已选默认模板，管理员可以自行创建和发布。
2. 默认选择与强制策略分离；更换默认指针不重绑已有规则，发布模板新版本能追踪所有引用规则的应用结果。
3. 验证排序、显式默认动作、空集合、临时条目到期及上级拒绝不能被子级允许覆盖。
4. 同账号多 Agent、跨租户引用、设备转移、旧会话及旧缓存不能扩大授权。
5. IPv4 及 IPv4-mapped 来源规范化、地区未知/不可用与地址库更新执行明确语义；IPv6 HTTP/承载不被误当作 IPv6 TCP/UDP 业务或套用用户业务 ACL。
6. TCP 长连接撤权后停止，其他复用流继续；UDP 映射过期、伪造返回及端口变化正确处理。
7. socket/TUN 路径使用同一原始 IPv4 来源判断；DNS 重解析、仅有 AAAA 的目标、IPv4 分片和目标四元组冲突不绕过策略或扩大地址族范围。
8. 验证内核状态清理、应用 ACK、租约到期、无效发布、重启及云控失联，不遗留旧许可转发。
9. 模拟高 PPS 拒绝与批量统计，验证队列、日志和指标有界，业务资源与物理资源计量清楚。
10. 独立验证 Linux 客户端保源与 Windows 普通转发的能力边界，不修改无关宿主机规则；HTTP(S) 不被 TCP/UDP 模板绑定或业务过滤误伤。高 PPS、大规模并发及其他已暂缓测试不作为本轮完成条件。
