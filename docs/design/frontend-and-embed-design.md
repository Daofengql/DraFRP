# 前端与二进制嵌入设计

> 2026-11-01 同步网络设计：TCP/UDP 仅 IPv4，HTTP(S) 入口与客户端—服务器承载可双栈；每服务器两个专用承载端口，TUN 仅属于 Linux 客户端。本文描述展示目标，本轮不修改前端或中控实现，实际界面与待补项见 [实现与验收记录](../reference/IMPLEMENTATION.md)。

## 1. 技术方向与范围

管理前端采用 React + TypeScript + Material UI，使用 Vite 构建 SPA。用户控制台与管理员控制台共用一套应用、主题和基础组件，通过服务端权限能力控制各自可见的页面与操作。

系统分别交付云控服务端、边缘服务端、客户端三个独立二进制。发布模式只将完整管理前端嵌入云控，由单实例云控同源提供页面、API 和状态事件，采用 Go 的 go:embed；实际实现与尚未交付的目标分别记录在 IMPLEMENTATION.md。

开发模式使用 Vite 热更新并代理 API；运行 release 二进制不要求安装 Node.js、部署独立 dist 目录或访问外部 CDN。边缘的 HTTP 系统错误页仍由边缘本地提供，不依赖管理前端在线。

MySQL 和可选 Redis 只由云控连接，Redis 故障时使用云控自管理内存库；浏览器、边缘和客户端不直接接入这些存储。职责与恢复机制见 [运行与存储设计](storage-and-runtime-design.md)。

本文定义目标页面、交互和工程方案，已有界面与实现说明见 [web/README.md](../../web/README.md)。具体 ACL、地区清单和模板内容继续由管理员后续添加，前端不附带示例策略或初始化策略。

## 2. 前端基础组件与数据层

| 部分 | 方案 |
| --- | --- |
| 页面与类型 | React、TypeScript 严格模式 |
| 视觉组件 | MUI Core、Emotion、Material Icons，统一 ThemeProvider 与 CssBaseline |
| 路由 | React Router，按功能页面延迟加载 |
| 服务端数据 | TanStack Query，统一请求、缓存、失效与错误处理 |
| 表单 | React Hook Form + Zod，服务端继续独立校验 |
| 列表 | 优先 MUI Table + 服务端筛选/排序/分页，不默认依赖 Pro/Premium 组件 |
| 趋势图 | 选择能满足基础流量曲线的开源组件，遵循统一时间、单位和空数据语义 |
| 状态通知 | 同源 SSE 推送状态变化，指标按云控已有汇总周期读取；断线时有界轮询 |
| API 类型 | 后端接口契约稳定后从 OpenAPI 等契约生成，不在页面重复定义资源结构 |

不把全部业务数据放进全局状态仓库。资源状态使用查询缓存，页面筛选保存在 URL，未提交表单留在本页；主题、导航折叠等少量偏好单独保存。

## 3. 控制台布局与导航

采用适合运维管理的桌面布局：顶部为当前空间、面包屑、主题和账号菜单，左侧为功能导航，主区域展示当前资源及操作。桌面侧栏建议约 240px、顶部约 64px，主体使用 MUI 间距体系；窄屏改为抽屉导航，表单字段按宽度自然堆叠。

默认提供跟随系统的浅色/深色主题，使用统一主色、适度分隔线和清晰表格。状态同时使用文本与颜色；配置说明、错误详情和最后观测时间不只依赖悬浮提示。字体和图标随产物发布，中文使用本地系统字体回退。

### 3.1 用户控制台

| 页面 | 核心内容 |
| --- | --- |
| 概览 | 设备/规则状态、需处理的问题、账号共享用量和近期变化 |
| 设备 | 多 Agent 列表、绑定入口、设备详情、能力与连接情况 |
| TCP/UDP 隧道 | 来源入口到目标的规则列表、创建/编辑、状态和诊断 |
| HTTP(S) 站点 | 域名、目标、Host、回源 TLS、可信来源头和错误页状态 |
| 域名与证书 | 域名归属验证、公网证书、有效期和分发状态 |
| 用量 | 账号总额、多设备/多边缘消耗、速率波动及受限原因 |

当前空间影响所有资源列表和创建表单。切换空间时清理旧选择，按空间重新取数，查询缓存键包含空间身份；同名设备和相同本地目标也不能混用。用户只能选用有授权的边缘，不能进入节点运维配置。

### 3.2 管理员控制台

有平台管理权限时显示管理入口；租户内的管理权限不自动等于平台管理员。

| 页面 | 核心内容 |
| --- | --- |
| 平台概览 | 节点状态、容量、配置应用异常和汇总用量 |
| 用户与空间 | 用户、资源归属、权限和停用状态 |
| 边缘节点 | Linux 节点身份、IPv4 业务监听、双栈 HTTP(S)、两个专用承载端口及其实际监听/连接状态 |
| 公网端口池 | 业务端口可用范围、占用、保留与释放进度 |
| 账号配额 | 基准/峰值/突发信用、并发、流量周期与跨边缘份额 |
| TCP/UDP ACL 模板 | 空模板创建、草稿、发布、默认绑定、强制策略及引用影响 |
| 审计与系统设置 | 配置变更、凭据/授权操作、服务版本、MySQL 健康与当前临时存储后端 |

权限来自服务端返回的操作能力；路由和按钮隐藏只用于交互，所有读取和写入仍由后端校验资源归属与操作权限。

### 3.3 登录与设备绑定

登录和设备授权页面位于控制台之外的简化布局。Agent 展示的 URL/绑定码引导用户登录、选择空间、核对设备并确认绑定，完成后展示该设备详情入口。

绑定页处理过期、已使用、取消和身份冲突；页面不领取或展示设备私钥、长期设备凭据，也不将浏览器登录会话交给 Agent。当前只设计这一流程，不预先选定账号登录提供方。

## 4. 多 Agent 设备页面

设备列表展示名称、设备标识、平台/版本、在线状态、最后心跳、规则数和能力摘要。默认以列表为主，支持按状态筛选和搜索，避免为每台设备使用大型卡片占据页面。

设备详情分为概况、规则、边缘连接、能力和事件：

- 概况区分控制会话在线、边缘承载在线和实际业务是否就绪。
- 规则展示该设备自己的 TCP/UDP 与 HTTP(S) 配置，不自动合并同账号其他设备。
- 边缘连接分别展示每个 Agent—边缘组合的 QUIC/TLS、实际 IPv4/IPv6 承载、活动流、延迟、回退原因和上报时间；未采集的地址族观测明确留空。
- 能力分别展示普通 IPv4 socket、Linux IPv4 TCP/UDP 原生保源、TUN 权限及回程检测结果；Windows 明确不支持保源，不提供 IPv6 原生保源选项。
- 会话冲突、旧版本、目标错误和配置应用失败提供可理解的原因与处理入口。

TUN 是 Linux 设备本地选择的能力。面板展示状态和本机启用说明，不能通过云控开关绕过本地网络权限授权；接口存在也不能直接显示为透明保源就绪。关闭 TUN 后可使用普通 socket 转发，严格 native 规则能力不足时停止并提示显式改选 socket，不静默降低来源要求。

撤销设备前展示关联规则与中断影响，只影响该设备。规则迁移必须显式选择目标 Agent 并重新检查能力，不提供同账号自动接管的假象。

## 5. TCP/UDP 隧道创建与详情

### 5.1 创建流程

建议使用独立创建页及分步表单，简单编辑可复用同一字段组件：

1. 选择 TCP 或 UDP、名称及目标 Agent。
2. 选择获准使用的边缘和公网入口，申请端口；候选端口不是已占用承诺，最终由服务端事务分配。
3. 配置 Agent 侧 IPv4 目标地址/端口或可解析到 IPv4 的域名，选择普通转发或原生保源，并显示设备实际能力；IPv6 字面量不作为 TCP/UDP 目标选项，仅有 AAAA 的目标错误由运行时明确报告。
4. 展示 TCP/UDP 默认 ACL 模板来源及继承限制；有权时允许改选管理员发布的模板。没有模板时展示真实空状态。
5. 配置可选的规则子上限，展示账号和节点约束，确认后提交。

切换协议、设备或边缘时重新校验依赖字段；不自动保留已失效的端口、保源能力或 ACL 选择。所选目标地址始终解释为该 Agent 可达的地址，不把它误认为云控的本机地址。

### 5.2 规则列表与详情

列表主要列为名称、协议、公网入口、目标设备/服务、运行状态与最近用量。行内提供详情和操作菜单，批量操作仅在后端能逐项报告结果时开放。

详情优先显示入口 → 边缘 → Agent → 目标的关系，下面展示配置、应用进度、访问策略、用量和事件。高级协议参数与版本信息收纳在详情，普通用户不需要理解承载内部帧格式才能创建规则。

设备在线、隧道可用、规则配置已应用、目标可达分别显示。未知或尚未检查的目标状态显示“未检查”，不显示为健康；配置提交成功显示“已保存，正在应用”，不能直接宣告服务已经可用。

应用进度展示期望规则版本、Agent/边缘已应用版本、授权与能力情况。编辑时携带预期版本；并发冲突保留用户输入并提示比较，不覆盖其他人的修改。

停用、删除、迁移设备、修改目标或收紧策略前显示现有连接中断与资源释放影响。删除已提交但边缘尚未关闭时显示“正在释放”，不能把端口立即当成空闲。

## 6. HTTP(S) 站点页面

站点单独管理，创建页包含入口域名、边缘、公网证书、目标 Agent、回源 HTTP/HTTPS、Host、SNI、信任材料和超时。高级设置按需展开，默认回源证书校验仍由 Agent 执行。

站点详情展示域名验证、证书部署、Agent/隧道、回源结果与来源头行为。来源信息通过 Agent 注入可信 HTTP 头，不显示 TCP/UDP 原生保源开关，也不引入 ACL、地区模板或 WAF 页面。

站点公网入口可以是 IPv4/IPv6，支持 IPv6 访客访问单栈 IPv4 回源；来源头保留实际访客 IPv6。页面区分公网入口、外层承载和回源地址，不能因 HTTP 双栈或承载 IPv6 就显示已支持 IPv6 TCP/UDP 转发。来源头按请求生成，回源连接池无需按访客 IP 拆分，HTTP 不要求开启 TUN。

代理故障与目标自身响应分开说明：离线/隧道未就绪为 503，回源连接/TLS 故障为 502，超时为 504；目标自己的 4xx/5xx 不标成系统替换错误。错误页预览标记为预览，不虚构线上请求记录。

证书页面展示元信息与部署状态；私钥仅在确需上传时提交，不在后续查询或详情页回显。

## 7. 用量与传输状态

### 7.1 账号共享用量

账号总览聚合同一配额主体下的所有设备、规则和边缘，另提供按设备/边缘查看的明细。基准速率、峰值护栏、窗口平均速率、突发信用、周期流量和并发分别表达。

曲线使用服务端返回的采样区间及统计截至时间，不通过前端补点伪造秒级实时数据。允许范围内的短时速率上浮不显示为故障；无数据使用空状态或“暂无统计”，不当成零。

方向统一为上传“公网访问者 → 目标服务”、下载“目标服务 → 公网访问者”。bit/s 与 byte/s 的展示转换统一处理；业务计量与物理接口流量分别标识。受限原因区分账号预算、规则子上限、节点容量和链路条件。

### 7.2 Agent—边缘传输

在设备连接详情和节点详情中分别展示 QUIC/TLS 与 IPv4/IPv6 选择，包含首选/实际模式、候选失败及回退原因、活动承载数和观测时间。一个 IPv6 候选失败不等于 UDP 整体不可用；多条承载可以处于混合状态，不能仅用一个“UDP 已连接”覆盖全部业务。缺少实际地址族数据时不从配置或域名存在 AAAA 推导结果。

隧道链路 RTT 与目标响应耗时分开显示；传输层的低 RTT 不代表目标应用响应一定更快，数据尚未采集时不展示虚构的加速比例。

节点的一个 UDP 与一个 TCP 专用承载端口、双栈 HTTP(S) 入口及 IPv4 业务端口池分别说明。普通用户主要看自动选择结果，现有中控配置与权限机制沿用；本轮不增加端口范围扫描、IPv6 业务开关或新的管理流程。

完整传输协商、并发与故障语义见 [传输协议与承载设计](transport-protocol-design.md)。

## 8. ACL 模板页的内容边界

管理员首次进入看到空列表和“创建模板”，不会出现系统编写的预制 ACL。新建页从空草稿开始，提供匹配字段、排序、动作、默认动作及适用范围等编辑能力；地区集合也由管理员填写。

默认模板、强制策略和用户是否可替换分别显示。发布前展示受影响规则，发布后展示各节点期望与实际版本；更换默认选择与发布模板新版本是不同操作。

用户侧只展示有权使用的已发布模板、默认来源与完整继承结果。策略模拟解释匹配条目和默认动作，不冒充端到端连通性测试。具体语义遵循 [TCP/UDP ACL、模板与防火墙设计](tcp-udp-acl-firewall-design.md)。

## 9. API、状态同步与交互约定

建议 API 统一放在 /api/v1/，覆盖登录会话与能力、空间、设备/绑定、规则、站点、证书、用量、节点、配额、模板和操作审计。接口提供分页、结构化错误、观测时间及资源版本；权限不足与资源不存在按服务端约定显示。

登录态优先采用同源 HttpOnly Cookie，发布环境通过 TLS 提供；写操作的 CSRF 校验与会话失效处理统一完成。设备凭据和长期管理令牌不存入前端持久化存储。前端不把跨空间 ID 或浏览器角色当作可信授权依据。

一次会话集中维护状态事件连接，事件用于更新明确的状态或让查询失效；断线恢复时重新拉取快照，避免永久漏掉变化。状态变更推送与周期用量汇总分开，前端不能因为图表打开就要求节点高频上报。

兜底轮询采用可配置间隔、退避和页面可见性控制，避免每行资源单独发请求。事件与响应都按空间和版本处理，切换空间后丢弃旧上下文的迟到结果。

提交使用服务端版本校验，创建类操作使用幂等标识应对网络重试。启用、撤销和发布等动作等待真实应用结果，不用乐观更新伪造就绪；轻量名称修改才考虑可回滚的乐观展示。

## 10. 路由与静态资源服务

第一阶段建议固定控制台基础路径 /console/，根路径可重定向到控制台。Vite base、React Router basename 与后端挂载前缀保持一致，反向代理保留此前缀，不允许只改其中一处。

| 路径范围 | 处理方式 |
| --- | --- |
| /console/ 及合法前端页面 | 已嵌入的 SPA 页面，直接刷新详情页仍可打开 |
| /console/assets/ | 带内容哈希的嵌入静态资源；缺失资源返回真实 404 |
| /api/v1/ | API 或事件流，不进入 SPA fallback |
| /auth/ | 后端认证回调等服务路由，不进入 SPA fallback |
| /healthz、/readyz | 服务探针，按服务自身语义返回 |
| 其他服务路径 | 保留服务端处理，不能统一返回前端 HTML |

SPA fallback 仅用于控制台页面的 GET/HEAD 导航；缺失脚本、样式、图片和非法方法不能得到 index.html。未知前端页面由应用展示 404，API 未找到继续返回 API 错误。

index.html、入口版本信息及会话相关响应不使用长时间公共缓存；内容哈希资源可长期 immutable 缓存。第一阶段不引入 Service Worker，避免离线缓存干扰配置状态与版本切换。压缩服务需正确处理 Content-Type、Content-Encoding、Vary、HEAD 和条件请求。

页面版本与 API 版本同 release 生成，暴露 build_id 与 API 兼容信息用于诊断。单实例云控升级重启后，旧标签页遇到资源更新时提示刷新并保护未提交表单，避免无限自动刷新；重连后重新取得配置与状态快照。

## 11. 目录与 release 构建

建议目录结构，尚未创建：

~~~text
cmd/
  drafrp-cloud/           云控入口：业务存储、API 和嵌入前端
  drafrp-edge/            精简边缘入口：规则执行与转发
  drafrp-client/          客户端 Agent 入口：设备连接与目标访问
web/
  src/
    app/                 路由、提供器、权限与主题
    features/            设备、隧道、站点、用量及管理功能
    shared/              API 客户端、基础组件、格式化与错误处理
  public/                本地静态素材
  dist/                  Vite 生成产物
internal/webui/
  assets_release.go      release 构建标签，嵌入本包 dist
  assets_dev.go          非 release 构建，不依赖前端产物
  dist/                  构建流程复制，生成文件不作为手工源码维护
~~~

go:embed 的路径相对于 Go 源文件所在包，不能通过 ../../web/dist 引用包外目录。因此由 release 流程把 web/dist 复制到 internal/webui/dist，嵌入层通过 fs.Sub 等方式暴露只读文件系统。

release 是项目显式定义的 Go 构建标签，Go 不会根据优化级别自动切换此模式。非 release 文件保证普通后端开发和测试不依赖一个已存在的前端 dist；release 文件缺少真实产物时应构建失败，不用空占位页面掩盖。

构建顺序：

1. 使用锁定的 Node/包管理器及依赖锁文件安装前端构建依赖。
2. 执行类型检查、代码检查与前端生产构建。
3. 清理上一次生成目录，复制本次 dist 并校验 index、引用资源和构建标识。
4. 分别编译三个目标；以 release 标签编译云控并嵌入静态产物，边缘/客户端不引用完整管理前端或业务数据库初始化包。
5. 在不带前端目录的环境启动产物，验证页面、深层路由、API、登录会话及版本信息。

~~~mermaid
flowchart LR
    Source["React / TypeScript / MUI"] --> Vite["Vite 生产构建"]
    Vite --> Assets["生成静态资源与 build_id"]
    Assets --> Embed["Go release 构建 / go:embed"]
    Backend["云控服务"] --> Embed
    Embed --> Binary["云控二进制：页面 + API"]
~~~

开发时浏览器打开 Vite，/api 与认证相关请求代理到本地云控。发布时静态文件直接从嵌入文件系统读取，API 保持同源；站点地址、会话材料和密钥不写入前端构建环境变量作为动态配置。

前端公开运行配置只提供必要的部署信息和能力。严格 CSP 与 Emotion 样式 nonce 一起设计，不能发布后再用不兼容的样式策略导致 MUI 界面失效。

## 12. 实现顺序与后续验收

先完成主题、导航、登录与权限框架，再打通设备绑定 → 创建 TCP/UDP 规则 → 等待应用 → 查看状态的完整路径，随后补 HTTP(S)、用量、节点/配额与空 ACL 模板管理。release 嵌入从第一个可运行页面开始纳入构建，不留到所有页面完成后补接。

以下为目标检查清单，已完成项与新增双栈展示的待补项以 IMPLEMENTATION.md 为准：

1. 验证多空间和多 Agent 切换、权限变化、迟到请求及缓存隔离。
2. 验证未绑定设备、未配置模板、无统计、离线、应用失败和未知健康状态等真实空/异常状态。
3. 验证创建端口竞争、版本冲突、提交重试、删除等待释放和设备撤销影响。
4. 验证 Linux socket/TUN 与 Windows 普通转发能力区别、IPv4/IPv6 承载和 UDP 优先/TCP 兜底分别展示；HTTP 双栈来源头不出现原生保源或 TCP/UDP ACL 选项。
5. 验证统计延迟、弹性速率、方向与单位，不把允许的突发显示为故障。
6. 验证键盘操作、表单错误、明暗主题、窄屏和长地址，不依赖颜色识别状态。
7. 验证无 Node/无外部 dist 时的 release 页面、深层链接、静态 404、API 404、缓存和旧标签页升级。
